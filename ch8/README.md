# ch8 — 변동성 돌파 전략 (한국투자증권 모의투자)

8장 실습 기록입니다. 책은 대신증권 크레온 플러스로 ETF 자동매매를 만들지만,
여기서는 **한국투자증권(KIS) Open API의 모의투자**로 바꿔서 진행합니다.
모의투자로 충분히 연습한 뒤 같은 코드를 실전 계좌로 전환하는 것이 목표입니다.

## 책과 다르게 한 이유

| | 책 (대신증권 크레온 플러스) | 이 실습 (한국투자증권 Open API) |
|---|---|---|
| 연결 방식 | 증권사 프로그램 + `win32com` | REST API (`requests`) |
| 파이썬 | 32비트, 관리자 권한 필요 | 지금 쓰는 64비트 `quant.venv` 그대로 |
| 연습 환경 | 실제 계좌, 실제 돈 | 모의투자 (가상 자금 1,000만 원) |
| 실전 전환 | - | `.env`의 `KIS_MODE`만 바꾸면 됨 |

## 준비 과정 (2026-11-17)

1. 한국투자 앱에서 비대면으로 계좌 개설: 계좌 종류는 "국내/해외 주식"
   (종합매매계좌). 개인연금, CMA는 이 용도에 맞지 않음
2. 한국투자증권 홈페이지 회원 가입 후 로그인
3. 모의투자 신청: "트레이딩" → "모의투자"에서 리그구분 "국내주식",
   1,000만 원, 3개월로 신청 → 모의 계좌번호 발급
4. KIS Developers 서비스 신청: 모의투자용과 실전투자용 APP KEY,
   APP SECRET을 각각 발급 (APP SECRET은 발급 직후 바로 저장)
5. `quant_실습\.env`에 저장 (`.env`는 git 추적 제외)

   ```
   KIS_MODE=mock

   # 모의투자
   KIS_APP_KEY=...
   KIS_APP_SECRET=...
   KIS_ACCOUNT_NO=12345678-01

   # 실전투자
   KIS_REAL_APP_KEY=...
   KIS_REAL_APP_SECRET=...
   KIS_REAL_ACCOUNT_NO=12345678-01
   ```

### 모의투자와 실전투자 구분

- `KIS_MODE=mock`(기본값): 모의투자 서버에 접속하고 `KIS_APP_KEY`,
  `KIS_APP_SECRET`, `KIS_ACCOUNT_NO`를 사용
- `KIS_MODE=real`: 실전 서버에 접속하고 `KIS_REAL_`로 시작하는 값만 사용
- `KIS_MODE`를 직접 `real`로 바꾸지 않는 한 실전 계좌로는 접속도 주문도
  되지 않음. 실전 키를 `.env`에 넣어 두기만 하는 것은 영향 없음

| | 모의투자 | 실전투자 |
|---|---|---|
| 접속 주소 | `https://openapivts.koreainvestment.com:29443` | `https://openapi.koreainvestment.com:9443` |
| 거래 코드(TR ID) 첫 글자 | `V` (예: `VTTC8434R`) | `T` (예: `TTTC8434R`) |
| 호출 간격 | 1초 (호출 제한이 낮음) | 0.1초 |

## 8_2.py — 변동성 돌파 전략의 매수 목표가 계산

### 변동성 돌파 전략

오늘 주가가 "오늘 시가 + 어제 변동폭 × K"를 넘어서면 상승 추세로 보고
매수하고, 장 마감 전에 전부 파는 단기 전략입니다. 책과 같은 규칙을 씁니다.

- 목표가 = 오늘 시가 + (어제 고가 - 어제 저가) × K, K = 0.5
- 매수 조건: 현재가 > 목표가, 현재가 > 5일 이동평균, 현재가 > 10일 이동평균
  (세 가지 모두 만족)
- 이동평균은 어제까지의 종가로 계산

### 대상 ETF

| 종목코드 | 이름 |
|---|---|
| 069500 | KODEX 200 |
| 102110 | TIGER 200 |
| 229200 | KODEX 코스닥150 |
| 133690 | TIGER 미국나스닥100 |
| 360750 | TIGER 미국S&P500 |
| 114800 | KODEX 인버스 (11-17 추가) |
| 251340 | KODEX 코스닥150선물인버스 (11-17 추가) |

인버스 ETF는 지수가 내리면 가격이 오르는 상품입니다. 프로그램은 오르는
종목을 사는 기능만 있어서, 하락장에서도 매수가 일어나도록 추가했습니다.
레버리지(2배) 상품은 넣지 않았습니다. 대상이 7개여도 하루 최대 5종목
제한은 그대로입니다.

`8_2.py` 위쪽의 `SYMBOLS`에서 바꿀 수 있습니다.

  돈과 다르므로, 자동매매에서 매수 금액을 정할 때는 그대로 쓰면 안 됩니다.

### 주문 안전장치

- `8_3.py`는 모의투자(`KIS_MODE=mock`)에서만 실행되고, 실전 모드면 주문
  없이 종료
- 실전 주문은 별도로 잠겨 있음: `KIS_MODE=real`이어도 `.env`에
  `KIS_REAL_ORDER=yes`가 없으면 `kis.py`의 매수·매도가 거부됨

## 8_4.py — 변동성 돌파 전략 ETF 자동매매

책의 `EtfAlgoTrader.py`에 해당합니다. 하루 동안 켜 두면 아래 순서로
동작하고 스스로 종료합니다.

| 시간 | 동작 |
|---|---|
| 09:00~09:05 | 전날 팔지 못한 대상 ETF가 있으면 전부 매도 |
| 09:05~15:15 | 대상 ETF를 감시하다가 매수 조건을 만족하면 최유리 지정가 매수 |
| 15:15~15:20 | 보유한 대상 ETF를 전부 시장가 매도하고 종료 |
| 15:20 이후 | 종료 |

### 매매 기준

- 매수: 현재가 > 목표가, 현재가 > 5일 이동평균, 현재가 > 10일 이동평균을
  모두 만족할 때 (목표가 = 오늘 시가 + 어제 변동폭 × 0.5)
- 매수 규모: 최대 5종목, 종목당 시작 시점 주문 가능 금액의 19%
  (5종목 × 19% = 95%, 나머지는 가격 변동과 수수료 여유분). 종목당 하루 한 번
- 매도: 가격과 상관없이 15:15에 전부 매도. 손절 기준은 없음
- 알림: 시작, 매수, 매도, 오류, 매시 30분 잔고를 슬랙으로 전송

조건을 만족하는 종목이 없는 날은 매수도 매도도 하지 않고 끝나는 것이
정상입니다. 강하게 오르는 날에만 매수하는 전략이기 때문입니다.

### 책과 다른 점

- 매수는 최유리 지정가 후 미체결 잔량 취소, 매도는 시장가
  (책은 매수 최유리 FOK, 매도 최유리 IOC. 아래 "주문 방식" 참고)
- 목표가와 이동평균은 하루에 한 번만 계산 (모의투자 호출 제한 때문)
- 매도는 대상 ETF만 (책은 계좌의 모든 종목을 매도. 실전 계좌에 따로 보유한
  주식을 건드리지 않기 위함)
- 다시 실행해도 이미 보유한 종목은 다시 사지 않고, 주문이 실패한 종목도
  그날은 다시 시도하지 않음
- 매수 금액은 잔고의 예수금이 아니라 "주문 가능 금액"(매수가능조회)으로 계산

### 실행 결과 (2026-11-17)

```

```

이날은 현재가가 목표가와 이동평균 아래여서 매수 조건을 만족한 종목이
없었습니다. 테스트와 수정으로 몇 번 껐다 켠 뒤, 12:30부터 장 마감까지 일반
모드로 계속 돌린 결과입니다 (슬랙 알림).

- 명령 프롬프트 창 안을 클릭하면 출력이 멈출 수 있음 (`Enter`나 `Esc`로 해제)

### 테스트 모드 (`python 8_4.py --test`)

조건이 맞는 날이 올 때까지 매매를 볼 수 없어서, 전체 흐름을 바로 확인하는
테스트 모드를 추가했습니다. 매수 조건과 상관없이 대상 ETF를 1주씩(최대
5종목) 사고, 3분 뒤 전부 판 다음 종료합니다. 모의투자에서만, 평일
09:05~15:10 사이에만 동작합니다.

### 주문 방식: 매수는 최유리 지정가, 매도는 시장가

처음에는 매수와 매도 모두 시장가로 만들었고(위 테스트 모드 결과가 그
버전), 이후 매수만 최유리 지정가로 바꿨습니다.

| | 주문 방식 | 이유 |
|---|---|---|
| 매수 | 최유리 지정가 | 돌파 순간에는 호가가 얇아져서, 시장가로 사면 목표가보다 비싸게 체결될 수 있음. 최유리 지정가는 가장 싼 매도 가격(매도 1호가)에서만 체결됨 |
| 매도 | 시장가 | 15:15 일괄 매도는 가격보다 전량 체결이 중요함 |

최유리 지정가는 매도 1호가에 나온 물량만큼만 체결되고 나머지는 미체결로
남을 수 있습니다. 그래서 매수 주문 뒤 2초 간격으로 최대 3번 잔고를 확인하고,
다 체결되지 않았으면 미체결 잔량을 취소합니다. 결과에 따라 슬랙 알림이
"매수", "매수(일부 체결)", "매수 미체결" 중 하나로 옵니다. 일부만 체결돼도
그 종목은 그날 다시 사지 않습니다.

주문구분 코드는 증권사마다 다릅니다. 한국투자증권 API(`ORD_DVSN`)는
`00` 지정가, `01` 시장가, `03` 최유리지정가입니다. 키움증권은 `03`이 시장가,
`06`이 최유리지정가라서, 다른 증권사 자료의 코드를 그대로 쓰면 안 됩니다
(한국투자증권에서 `06`은 장후 시간외 주문).

책의 실제 방식은 매수 최유리 FOK(전량 체결 아니면 전량 취소), 매도 최유리
IOC(체결되는 만큼만 체결, 나머지 취소)이고, 매도 시점은 다음 날 시초가가
아니라 당일 15:15입니다.

## 매일 자동 실행 (작업 스케줄러)

책처럼 윈도우 작업 스케줄러에 등록해서 평일 아침에 자동으로 실행되게
합니다.

- `quant_실습\run_trader.bat`: `ch8` 폴더로 이동해 가상환경의 파이썬으로
  `8_4.py`를 실행하는 배치 파일
- 로그: 스케줄러로 실행하면 화면을 못 볼 수 있어서, 화면 출력을
  `ch8\logs\날짜.log`에도 기록 (`logs/`는 git 추적 제외)
- 중복 실행 방지: 프로그램이 두 개 동시에 돌면 같은 종목을 두 번 살 수
  있으므로, 이미 실행 중이면 새로 켜진 쪽이 바로 종료

등록 (평일 08:50):

```
schtasks /create /tn "ETF_AutoTrade" /tr "C:\workspaces\quant\quant_실습\run_trader.bat" /sc weekly /d MON,TUE,WED,THU,FRI /st 08:50
```

확인은 `schtasks /query /tn "ETF_AutoTrade"`, 삭제는
`schtasks /delete /tn "ETF_AutoTrade" /f`.

등록 후 작업 스케줄러에서 `ETF_AutoTrade`를 더블클릭해 옵션 두 개를 켭니다.

| 탭 | 옵션 | 효과 |
|---|---|---|
| 설정 | 예약된 시작 시간을 놓친 경우 가능한 한 빨리 작업 시작 | 08:50에 꺼져 있거나 절전 중이었어도, 컴퓨터를 켜거나 깨우는 순간 실행 |
| 조건 | 이 작업을 실행하기 위해 절전 모드 종료 | 08:50에 절전 상태의 컴퓨터가 스스로 깨어나 실행 (기종과 전원 설정에 따라 안 될 수 있음) |

2026-11-17에 등록하고 옵션을 설정한 뒤, 작업 스케줄러에서 우클릭 "실행"으로
배치 파일이 실행되고 슬랙 알림이 오는 것을 확인했습니다 (장이 끝난
시간이라 시작 직후 바로 종료).

### 왜 08:50인가

장은 09:00에 열리지만, 토큰 발급과 잔고 조회를 미리 끝내고 09:00~09:05의
아침 정리(전날 남은 종목 매도)를 놓치지 않기 위해 여유를 둡니다. 일찍
켜도 매수는 09:05부터 시작합니다.

### 늦게 켜졌을 때의 동작

- 09:05 전: 평소와 같음
- 09:05 이후: 그 시점부터 감시. 이미 목표가를 넘은 종목은 켜지자마자 그때
  가격으로 매수하므로 돌파 순간보다 비싸게 살 수 있음
- 15:20 이후: 바로 종료

### 주의할 점

- 로그인된 상태여야 실행됨 (화면 잠금은 괜찮고, 로그아웃은 안 됨)
- 퇴근할 때는 "시스템 종료"가 아니라 "절전"으로 두고 충전기를 연결
- 장중에 컴퓨터가 절전에 들어가면 프로그램이 멈추므로, 윈도우 절전 시간은
  "안 함"으로 유지
- 공휴일에도 실행되지만 시세가 없어 아무것도 사지 않고 15:20에 종료
- 스케줄러는 `.env`의 `KIS_MODE`를 그대로 따름. 실전으로 바꾸면 매일 실제
  주문이 나가므로, 실전 전환 때는 스케줄러를 먼저 끄고 다시 판단

## 이 실습의 범위와 확장 방법

이 실습과 책 8장의 목적은 수익이 나는 전략을 완성하는 것이 아니라, 가장
단순한 규칙 하나로 자동매매의 전체 틀(증권사 연결 → 장중 감시 → 주문 →
청산 → 알림)을 처음부터 끝까지 만들어 보는 것입니다. 변동성 돌파는 규칙이
"목표가를 넘으면 사고, 정해진 시간에 판다" 두 줄이고 그날 사서 그날 팔기
때문에, 틀을 만드는 예제로 쓰기 좋아서 고른 전략입니다.

따라서 각자의 전략은 이 틀 위에서 로직을 바꾸거나 추가해서 만듭니다.
책의 규칙이 지금 시장에서도 통하는지는 검증하지 않았으므로, 그대로
실전에 쓰는 용도가 아닙니다.

### 파일별 역할

| 파일 | 역할 | 전략을 바꿀 때 |
|---|---|---|
| `kis.py` | 증권사 연결 (토큰, 시세, 잔고, 주문, 취소) | 그대로 사용 |
| `strategy.py` | 언제 살지 판단 (목표가, 이동평균, 매수 조건) | 주로 여기를 수정 |
| `8_4.py` | 하루의 흐름, 종목, 비율, 시간, 알림 | 종목, 금액, 매도 조건을 수정 |

### 바꿀 수 있는 것

- 종목: `8_4.py`와 `8_2.py`의 `SYMBOLS`에 종목코드를 넣으면 됨. ETF 대신
  일반 주식도 가능하고 섞어도 됨
- 매수 규모: `TARGET_BUY_COUNT`(최대 종목 수), `BUY_PERCENT`(종목당 비율)
- 매수 기준: `strategy.py`의 `K`(변동폭에 곱하는 비율), `is_buy_signal()`.
  6장의 볼린저 밴드, 삼중창 같은 다른 전략의 신호로 교체 가능
- 매도 기준: 지금은 시간(15:15)뿐. 아래 조건을 `8_4.py`의 감시 루프에 추가 가능

### 지금 로직에 없는 것: 장중 매도 조건

지금은 매수 후 많이 올라도, 많이 내려도 15:15까지 그대로 보유합니다.
책이 "오늘 강하게 오른 종목은 장 끝까지 흐름이 이어진다"고 가정하고
규칙을 시간 하나로 단순하게 둔 것입니다. 추가할 수 있는 조건은 다음과
같습니다.

| 조건 | 내용 | 대가 |
|---|---|---|
| 익절 | 매입가 대비 일정 비율 이상 오르면 매도 | 그 뒤 더 오르는 몫을 놓침 |
| 손절 | 매입가 대비 일정 비율 이상 내리면 매도 | 잠깐 내렸다 오르는 경우에도 손실 확정 |
| 고점 대비 하락 시 매도 | 매수 후 최고가에서 일정 비율 내려오면 매도 | 흔들림이 큰 종목은 일찍 팔림 |

조건을 넣으면 매매 결과가 달라지므로, 넣기 전에 과거 데이터로 넣었을 때와
안 넣었을 때를 비교해 보는 것이 순서입니다.

### ETF 대신 일반 주식으로 바꿀 때 달라지는 점

- 일반 주식은 팔 때 증권거래세가 붙음 (국내 주식형 ETF는 없음). 매일
  사고파는 전략이라 비용이 매번 쌓임. 세율은 실전 전에 확인 필요
- 개별 주식은 하루 변동폭이 커서 돌파가 자주 일어나지만 손실 폭도 커짐
- 실적 발표, 공시, 거래 정지 같은 개별 악재에 노출됨. 거래가 정지되면
  15:15에 팔지 못함
- 1주 가격이 종목당 주문 금액보다 비싼 종목은 살 수 없음 (건너뜀)
- 거래량이 적은 종목은 최유리 지정가 주문이 일부만 체결되거나 미체결로 끝남
